# Usability test pack

This is a proposed moderated study, not measured research. A starting target is reaching a relevant recipe within two minutes; validate or replace it from observed sessions.

## Participants and setup

Recruit a mix of occasional makers, enthusiasts and hosts; record cocktail frequency, inventory size and prior app use without assigning one group as primary. Use a clean release build and the supplied reference fixture. Obtain consent; do not capture private account or alcohol-consumption details unnecessarily.

Facilitator opening: “We’re testing the product, not you. Please think aloud. I may stay quiet so I can see what the interface communicates. You can stop at any time.” Do not explain the navigation or intended answer.

## Neutral tasks and observation criteria

| Scenario | Participant task | Observe | Proposed success signal |
| --- | --- | --- | --- |
| Small bar | “Set up bourbon, sugar syrup and eggs, then find something useful.” | Starter comprehension, ice decision, time, hesitation. | Reaches Tonight and one-away result without help. |
| Explain one-away | “Tell me why the Whiskey Sour is not ready and what is optional.” | Missing lemon vs garnish/equipment understanding. | Names lemon only as required addition. |
| Compare sorting | “Compare the two recommendation orders and choose the one you would use tonight.” | Availability trust, taste language, status retention. | Can still state readiness in Taste-led view. |
| Recognised scan/undo | “Add this vodka bottle, then reverse the addition.” | Permission primer, framing, lock feedback, Undo confidence. | Adds once and removes/corrects without help. |
| Unknown recovery | “The barcode is not found. Add the bottle for yourself.” | Manual route visibility, form burden, preservation. | Saves name/category without catalogue submission. |
| Stock change | “The bourbon bottle is empty. Update the app and check the effect.” | Mark empty language and recommendation refresh. | Uses Mark empty and can restore it. |
| Quick Select | “Ask the app to choose a drink. If none is ready, decide what to do.” | Eligibility trust, one-away consent, repeat response. | Understands selection and explicit expansion. |
| Make a round | “Prepare this for six people, leave midway, then return.” | Units, batch guidance, step controls, interruption recovery. | Correct count/units and resumed step; notices batching. |
| Purchase suggestion | “Choose what would expand this bar most and explain the count.” | Evidence trust and commercial tone. | Identifies category and supporting recipes/families. |
| Guest account | “After exploring as a guest, create an account and tell me what happened to your data.” | Backup expectation, conflict/retry comprehension. | Understands source preservation and confirmation. |

## Non-leading prompts

Use only after a pause: “What are you looking for?”, “What do you expect that to do?”, “What does this status mean to you?”, “What would you do next?”, “What makes you confident or uncertain?” Do not say “tap Scan”, “the garnish is optional” or “Taste-led is personalised”.

## Capture template

| Field | Record |
| --- | --- |
| Session ID / segment | Anonymised code; self-described context |
| Device / OS / build | Exact values |
| Task | Scenario name |
| Outcome | Complete / complete with prompt / incomplete |
| Time | Observed duration; do not overinterpret small samples |
| Errors and recovery | Action sequence and whether effort was lost |
| Think-aloud evidence | Short paraphrase; verbatim only with consent |
| Accessibility context | Text size, screen reader, motor/vision needs if volunteered |
| Severity | Blocks task / causes error / delay / cosmetic |
| Design implication | Hypothesis, not conclusion until synthesised |

## Evaluation

Prioritise task completion, harmful inventory mistakes, lost work, trust and recovery before preference or visual polish. Report sample size, recruitment bias and environment. Separate observed behavior from facilitator interpretation. A walkthrough by the team is heuristic QA, not a participant session.
